Pixels to Action: Document Intelligence RAG Pipeline

A multi-agent assistant that lets banking and legal teams ask questions about scanned and mixed-quality documents and get answers they can trace back to the exact page and region. Documents are understood once on arrival; questions are answered from that index, with a verifier between the model and the user.

Document / Image→Understanding→Reasoning→Answer / Action
1 · Understand the situation

Users, documents and scope

Who uses it

  • Operations analysts checking statements, transfers and KYC files
  • Legal / compliance reading clauses, dates and obligations in contracts
  • Reviewers who resolve low-confidence extractions
  • Auditors who need to see why an answer was given

What arrives

  • Native PDFs, scans, phone photos, faxes
  • Bank statements, loan contracts, powers of attorney, ID documents, invoices
  • Tables, stamps, signatures, handwritten notes
  • Spanish, Catalan and English; varying DPI and skew

Assumptions & constraints

  • Personal and financial data: GDPR, EU data residency
  • Every answer must cite its source document and page
  • No autonomous changes to records or money movement
  • Out of scope at first: video, voice, real-time streams

Pre-processing on arrival keeps query latency low and lets us validate extractions before anyone relies on them. Only low-confidence regions get re-read on demand.

  1. B1rules

    Query gateway

    Authenticate, apply role-based access, redact PII before any external model call, attach conversation context.

    out: scoped query
  2. B2orchestrator

    Router agent

    field lookup → SQL tool open question → RAG multi-doc → planner action ask → action agent
  3. B3retrieval

    Hybrid retrieve

    BM25 + vectors + metadata filters, then a cross-encoder reranker. Returns chunks with page crops.

    out: top-k evidence
  4. B4LLM

    Reasoning agent

    Drafts the answer citing doc, page and box. If evidence is low-confidence, re-reads the page image with the vision model.

    out: draft + citations
  5. B5guardrail

    Verifier

    Each claim must be supported by a cited chunk. Numbers are re-checked against the field store. Produces a confidence score.

    ● ≥ 0.80 → answer ● 0.50–0.80 → answer + warning ● < 0.50 → abstain, escalate
  6. B6human gate

    Answer or act

    Answer with highlighted source crops. Actions (flag discrepancy, open ticket, draft email) are proposed and run only after a person approves.

    out: answer · trace_id

AI responsibilities

How much autonomy

Autonomous

Read & extract

Classify, OCR, extract fields, index. Validated by rules, sampled by reviewers.

Autonomous, cited

Answer

Answer questions with citations, or abstain. Never answer without evidence.

Human approves

Recommend & act

Flag discrepancies, open tickets, draft replies. A person clicks to execute.

Never

Change records

No payments, no edits to core banking data, no legal decisions.

Where AI is the right tool

  • Reading degraded scans, stamps and handwriting (vision LLM)
  • Mapping varied layouts to one schema without a template per bank
  • Understanding the question and planning multi-document checks
  • Writing the answer in the user's language with citations

Where rules or classic ML are better

  • Image quality, deskew and blur scoring: classic CV, cheap and predictable
  • Checksums, totals, date logic: deterministic validation
  • Access control and PII redaction: never delegated to a model
  • Exact numeric answers: SQL over validated fields, not generated text

Failure modes

  • Misread digit in a scanned amount
  • Table rows merged or shifted
  • Answer drawn from the wrong client's document
  • Fluent answer with no supporting evidence
  • Instructions hidden inside a document (prompt injection)

Controls & fallbacks

  • Rule validation before indexing; failures go to review
  • ACL filter applied in retrieval, not in the prompt
  • Verifier blocks ungrounded claims; abstain below 0.50
  • Document text treated as data, never as instructions
  • PII redaction and EU-hosted models for sensitive types

Observability

  • One trace_id per question: chunks, prompts, model versions, scores
  • OCR confidence distribution per source, to catch a bad scanner
  • Abstention and reviewer-override rate over time
  • User thumbs-down feeds the golden set
5 · From concept to MVP

What we build first

MVP · 6–8 weeks

Statements and loan contracts, Q&A with citations

  • Two document types, Spanish only, PDFs and scans
  • A1–A6 and B1–B5; actions limited to "flag for review"
  • OCR and layout bought as a managed service; orchestration, validation and evaluation built in-house
  • Reuse this repo's RAG core (ChromaDB, sentence-transformers, Groq) with a multilingual embedder and BM25 added
  • Single router + reasoning agent; no planner yet
  • Golden set and evaluation harness built in week 1
Phase 2

More documents, more autonomy

  • KYC, powers of attorney, invoices; Catalan and English
  • Multi-document planner agent and cross-client analytics
  • Approved actions: tickets, drafted emails, CRM notes
  • Fine-tuned extractor for the highest-volume layouts
  • Active learning from reviewer corrections

Hypotheses to validate

  • OCR + vision LLM beats vision-only on scanned tables at lower cost
  • Citations cut analyst checking time by half
  • An abstain threshold keeps faithfulness ≥ 95 % without abstaining on more than 15 % of questions

Trade-offs we accept now

  • Pre-processing cost for documents nobody queries
  • Higher latency from the verifier in exchange for trust
  • Narrow scope: two types done well instead of ten done badly

Biggest risk · go criteria

  • Risk: poor scans of tables and handwritten notes drive extraction below target
  • Go to phase 2 when: targets above hold for 4 weeks and reviewers confirm the time saving
